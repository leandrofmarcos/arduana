### 🟢 FEAT-004 — Solicitação de Orçamento (`/solicitacoes`)

**Descrição:** Ponto de entrada do fluxo comercial. Registra a demanda do cliente por um serviço de importação.

**Campos do formulário:**
- Porto Origem *(obrigatório)*
- Porto Destino *(obrigatório)*
- Data *(obrigatório)*
- Cliente (opcional)
- Importador (opcional)
- Tipo de Container: 20', 40', LCL
- Peso (kg)
- Observação
- Despachantes consultados *(mínimo 1 na criação)*
- Documentos/Packlist anexos

**Código gerado:** `SOL-AAAA-NNN` (ex: SOL-2026-001)

**Comportamento automático na criação:**
1. Status inicial definido como `AguardandoCusto`
2. Para cada despachante adicionado: cria `CustoDespachante` com status `AguardandoCusto` (se ainda não existe vínculo)
3. Cria `OrcamentoVenda` com status `AguardandoDespachante` (se ainda não existe)

**Comportamento automático na edição — transição de aprovação:**
- Quando status muda de `AguardandoAprovacaoCliente` → `Aprovada`: cria `EmbarqueAduana` automaticamente com status `Previsto`

**Sub-seções da tela:**
- Tabela de despachantes com status, data de envio, código do custo gerado e status do custo
- Seção de Orçamento de Venda vinculado (modo edição)
- Seção de documentos/packlist

**Regra de negócio — proteção de vínculo:**
- Não é possível remover um despachante da solicitação se já há CustoDespachante gerado para ele

### 🟢 FEAT-005 — Custo Despachante (`/custos`)

**Descrição:** Wizard de 4 etapas para cálculo detalhado do custo de importação.

**Código gerado:** `CD-AAAA-NNN` (ex: CD-2026-001)

**Status disponíveis:**

| Status | Cor | Quando |
|--------|-----|--------|
| `AguardandoCusto` | Âmbar | Padrão ao criar / salvar durante edição |
| `Rascunho` | Cinza | Status legado / preenchimento parcial |
| `Finalizado` | Verde | Ao clicar em "Finalizar" |

**Wizard — 4 etapas:**

| Etapa | Conteúdo |
|-------|---------|
| 1 — Dados Gerais | Despachante, Importador, Portos, Container, Peso, FOB (USD/R$), CIF (USD/R$), Seguro, Taxa de Câmbio, Taxa Agente, Data, Observação |
| 2 — Licenças de Importação | Múltiplas LIs: NCM, Descrição, Valor, Data |
| 3 — Despesas | Lista de despesas com flag `entraBaseIcms` |
| 4 — NCMs e Impostos | NCMs vinculados com alíquotas → cálculo automático de II, IPI, PIS, COFINS, ICMS |

**Cálculo de impostos (Etapa 4):**
```
II       = base × aliII%
IPI      = (base + II) × aliIPI%
PIS      = base × aliPIS%
COFINS   = base × aliCOFINS%
ICMS     = (base + II + IPI) × aliICMS%
Total    = II + IPI + PIS + COFINS + ICMS
```

**Regras:**
- Status padrão ao criar: `AguardandoCusto`
- Botão "💾 Salvar" → mantém status `AguardandoCusto`
- Botão "✅ Finalizar" → muda status para `Finalizado`
- Exclusão em cascata: LIs → Despesas → NCMs Vinculados → Valores de Imposto
- Custo pode ser criado manualmente ou via Solicitação de Orçamento

### 🟢 FEAT-006 — Orçamento de Venda (`/orcamentos-venda`)

**Descrição:** Documento comercial com o preço total do serviço enviado ao cliente.

**Código gerado:** `OV-AAAA-NNN` (ex: OV-2026-001)

**Campos principais:**
- Cliente, Data, Container, Peso Bruto, Peso Líquido
- Frete Internacional, CIF (R$/USD), FOB (R$/USD), Taxa de Câmbio
- Honorários, Total Impostos, Total Despesas, Total Extras, **Total Geral**

**Composição do Total Geral:**
```
Total Geral = totalImpostos + totalDespesas + totalExtras + honorarios + freteInternacional
```

**Sub-entidades:**
- Despesas (Capatazia, THC, Armazenagem, etc.)
- Despesas Extras (segregadas para análise gerencial)
- Vínculos com CustosDespachante (N:M)

**Status disponíveis:**

| Status | Significado |
|--------|------------|
| `Rascunho` | Em elaboração |
| `AguardandoDespachante` | Criado via Solicitação, aguardando custo |
| `AguardandoOrcamentoVenda` | Em processo de composição |
| `Finalizado` | Aprovado e finalizado |

**Exclusão em cascata:** Despesas → Extras → Vínculos com Custos

### 🟢 FEAT-007 — Embarques Aduana (`/embarques`)

**Descrição:** Gestão operacional dos processos de importação em andamento.

**Código gerado:** `EMB-AAAA-NNN` (ex: EMB-2026-001)

**Campos do processo:**
- Cliente*, Despachante*, Porto Origem*, Porto Destino*
- Agente de Carga, Navio (ControleNavio), Exportador
- IMP, BL, Container, Peso (kg)
- ETD, ETA, Ref. Ominium, Ref. Agente, LI, Registro
- Aviso Previsão, Aviso Chegada, Data Registro DI, Data Desembaraço, Data Entrega
- Observação
- Vínculos opcionais: CustoDespachante, OrcamentoVenda, SolicitacaoOrcamento

**Nota:** Criação manual desabilitada na UI — embarques são criados automaticamente ao aprovar uma Solicitação.

**Pipeline de Status (imutável — seed do sistema):**

| Ordem | Nome | Código |
|-------|------|--------|
| 1 | Previsto | PREV |
| 2 | Aguardando | AGRD |
| 3 | Atracado | ATRC |
| 4 | Registrado | RGTD |
| 5 | Desembaraçado | DSMB |
| 6 | Entregue | ENTG |
| 7 | Finalizado | FNLZ |

**Funcionalidades da tela de Detalhe:**
- **Timeline visual** dos 7 status com marcação do status atual; clique em cada etapa abre modal de transição
- **Alteração de Status** com observação obrigatória; registra automaticamente no histórico
- **Edição inline** de campos operacionais (BL, Container, ETA, datas de registro, desembaraço, entrega, etc.)
- **Free Time** — cadastro de períodos de isenção de demurrage; cálculo automático de `dataFim = dataInicio + quantidadeDias`; alertas visuais de vencimento
- **Pagamentos do Processo** — controle por tipo (Cobrança Sinal, Sinal Pago, Fechamento Pago, Honorário, Outro) com datas previstas/efetivadas
- **Histórico de Status** — feed cronológico de todas as mudanças com usuário e observação

**Sub-view — Acompanhamento (`/embarques?acompanhamento=1`):**
- Visão de dashboard agrupada por status
- Filtros por cliente e status
- Acesso direto ao detalhe de cada embarque
- Menu lateral registrado com `[routerLinkActiveOptions]="{exact:true}"` para destacar somente a rota exata

**Exclusão em cascata:** Histórico de Status → FreeTimes → Pagamentos

### 🟢 FEAT-008 — Controle de Navios (`/controle-navios`)

**Descrição:** Gestão de navios/viagens com acompanhamento de embarques por navio.

**Cadastro:**
- Número da Viagem, Nome do Navio, Observação, Ativo
- Trajetos: múltiplos porta a porta com ETD, ETA e descrição

**Visão da tabela:**
- Exibe **apenas navios com embarques em andamento** (ordem < 6 — exclui Entregue e Finalizado)
- Colunas: Nº Viagem, Navio, ETA Destino (máximo ETA entre trajetos), Embarques, Trajetórias, Ações
- Sub-tabela expansível de embarques por navio: Código, Cliente, Container/BL, ETA, Status badge
- Sub-lista expansível de trajetos

**Ação ⚓ Atracado:**
- Visível apenas quando o navio possui embarques com ordem < 3 (anteriores a Atracado)
- Ao clicar: altera **em lote** todos os embarques elegíveis para status `Atracado (ATRC)`
- Registra histórico em cada embarque com observação referenciando nome e viagem do navio

**Exclusão em cascata:** Trajetos vinculados

## Fluxo de Negócio — Ciclo Completo

```
[Criação da Solicitação]
  SOL criada → status: AguardandoCusto
  ↓ (automático por despachante)
[Custo Despachante]
  CD criado → status: AguardandoCusto
  Despachante preenche wizard (4 etapas)
  CD finalizado → status: Finalizado
  ↓ (automático na criação da SOL)
[Orçamento de Venda]
  OV criado → status: AguardandoDespachante
  Operador vincula CD ao OV
  OV finalizado → status: Finalizado
  ↓ (edição da SOL)
[Aprovação]
  SOL: AguardandoAprovacaoCliente → Aprovada
  ↓ (automático)
[Embarque]
  EMB criado → status: Previsto (PREV)
  → Aguardando (AGRD)
  → Atracado (ATRC)  ← pode ser feito em lote via Controle de Navios
  → Registrado (RGTD)
  → Desembaraçado (DSMB)
  → Entregue (ENTG)
  → Finalizado (FNLZ)
```

## Regras de Negócio Consolidadas

### RN-001 — Código Interno
Todos os códigos seguem o padrão `PREFIX-AAAA-NNN`. São gerados automaticamente e nunca editáveis pelo usuário.

### RN-002 — Responsável Automático
O campo `responsavel` nas entidades é preenchido automaticamente com o `username` do usuário autenticado.

### RN-003 — Criação em Cascata na Solicitação
Ao criar uma Solicitação com N despachantes, o sistema cria automaticamente N `CustoDespachante` e 1 `OrcamentoVenda`. A criação é idempotente: verifica existência antes de criar.

### RN-004 — Status Padrão dos Custos
`CustoDespachante` criado automaticamente ou manualmente inicia sempre com status `AguardandoCusto`.

### RN-005 — Aprovação gera Embarque
A transição `AguardandoAprovacaoCliente → Aprovada` em uma Solicitação dispara automaticamente a criação de um `EmbarqueAduana` com status `Previsto`.

### RN-006 — Embarques visíveis no Controle de Navios
Apenas embarques com `ordem < 6` (não Entregue, não Finalizado) aparecem no Controle de Navios.

### RN-007 — Atracação em Lote
O botão ⚓ Atracado no Controle de Navios marca em lote todos os embarques com `ordem < 3` do navio para status `Atracado`.

### RN-008 — Free Time — Cálculo Automático
`dataFim` do FreeTime é calculada automaticamente: `dataFim = dataInicio + quantidadeDias`.

### RN-009 — Remoção Protegida
Não é possível remover um despachante de uma Solicitação se já existe um CustoDespachante gerado para ele.

### RN-010 — Delete em Cascata
| Entidade | Remove em cascata |
|----------|-----------------|
| SolicitacaoOrcamento | Despachantes + Documentos |
| CustoDespachante | LIs + Despesas + NCMs Vinculados + Valores de Imposto |
| OrcamentoVenda | Despesas + Extras + Vínculos de Custo |
| EmbarqueAduana | Histórico de Status + FreeTimes + Pagamentos |
| ControleNavio | Trajetos |

### RN-011 — Seed de Status de Embarque
Os 7 status de embarque são dados de sistema (seed imutável), inicializados na primeira carga. Não podem ser criados nem excluídos pelo usuário.

### RN-012 — Filtros de Busca
Toda listagem possui campo de busca textual que filtra sobre campos relevantes (código interno, nome, referências).

## Limitações Conhecidas desta Versão

| # | Limitação | Observação |
|---|-----------|-----------|
| L-001 | Armazenamento em `localStorage` | Dados persistem apenas no browser local; sem sincronização entre usuários |
| L-002 | Criação manual de Embarques desabilitada | Embarques criados apenas via aprovação de Solicitação |
| L-003 | Novo Embarque desabilitado na UI | Botão exibe mensagem "desabilitado" — feature planejada |
| L-004 | Sem controle de permissões por nível de acesso | Cadastros de Cargos e Níveis de Acesso existem mas não aplicam restrições de tela |
| L-005 | Sem integração com backend API | Frontend opera 100% com localStorage; API (.NET 8) em desenvolvimento paralelo |
| L-006 | Documentos armazenados como base64 | Limitação de tamanho do localStorage para arquivos grandes |
